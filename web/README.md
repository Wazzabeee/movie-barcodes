# Movie Barcodes in the browser

A static web app that generates movie barcodes entirely in the browser: movies are decoded by the browser from
the local file (no upload, no server), so it works on multi-GB files. No build step and no dependencies: plain
HTML, CSS and JavaScript modules.

## Run locally

```bash
python -m http.server -d web 8000
```

Then open http://localhost:8000 in Chrome or Edge. (ES modules do not load from `file://` URLs: a static server
is needed.)

## How it works

- `src/video.js`: frames are read through a `<video>` element: seek to the middle of each sampled frame, wait
  for it to be presented (`requestVideoFrameCallback`), draw it on a small canvas (256 px wide by default) and
  read the pixels back. Browsers do not expose the frame rate: it is measured from a few played frames.
- `src/color.js`: per-frame colors (`avg`, `smoothed`, `avg_linear`), the same math as
  `src/movie_barcodes/color_extraction.py`.
- `src/layout.js`: frame sampling (`i * frame_count // n`, like the Python package) and barcode drawing.
- `src/barcode.js`: one pass over a movie for all the selected methods. `src/app.js`: user interface.
  `src/files.js`: files, folders (File System Access API in Chromium, `webkitdirectory` elsewhere) and saving.

## Tests

```bash
cd web
npm test        # color math vs reference values from the Python package (Node >= 22, no dependencies)
npm run smoke   # end to end in headless Chrome on tests/sample.mp4, compared with Python (macOS Chrome path by default, CHROME=... otherwise)
```

`tests/fixture.json` is generated by the Python package:
`UV_NO_CONFIG=1 uv run python web/tests/generate_fixture.py` (from the repository root).

## Limits

- Chrome or Edge on desktop recommended. Safari and Firefox support fewer codecs and containers (no MKV in
  Safari); files the browser cannot decode get a clear error and the batch continues.
- Keep the tab visible and the window uncovered while it runs: browsers stop presenting video frames in
  background tabs (processing pauses and resumes).
- Colors are within a few levels (out of 255) of the Python package: the browser and OpenCV convert video
  frames from YUV to RGB slightly differently (about 1.5 levels on `tests/sample.mp4`).
- About 60-80 ms per sample: a 1920-sample barcode takes about 2-3 minutes per movie.
